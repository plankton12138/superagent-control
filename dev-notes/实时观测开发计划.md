# SuperAgent 实时观测开发计划

主画布是 SuperAgent 的运行架构。共享组件在画布上保持固定位置，工单随运行状态展开并行分支。点击节点或连线，在侧栏查询相应记录。PR 是查看交付历史的入口，Ticket 是串联执行记录的主键。

设计依据为 [领域模型](../dsh-superagent-prototype/docs/001-domain.zh-CN.md)、[系统架构](../dsh-superagent-prototype/docs/007-architecture.zh-CN.md) 和 [现有预览](../docs/SuperAgent实时观测设计.md)。中英文文档有出入时，以实际运行的代码和事件为准。

## 敲定的展示内容

| 区域 | 默认画在图上 | 点击或展开后的内容 |
| --- | --- | --- |
| 来源与线程 | 虚拟 IM、GitHub 的健康状态，活动 Thread，消息进入和后续输入流向 | Trigger 摘要、发送者、来源时间、系统收到时间、过滤或去重结果、实际收到消息的 Ticket、是否仅提供上下文 |
| Engine 与 Router | 新任务经 Eval 和 Policy Gate 成为候选，Router 主 Session 提交路由结果，由 Engine 记录 Decision。显示待评估、接单、归并、忽略、停止、不可用 | Thread 批次和候选送达时间、显式路由或模型研判、结构化原因、策略版本与授权范围。按实际记录区分路由动作和持久化决定 |
| Effects 与槽位 | 启动队列、输入投递队列、Worker 槽位和阻塞原因 | 展开 `assessment`、`launch`、`delivery`、`relay`、`notice`、`reply`。查排队、准备目录、等待槽位、重试、下次尝试时间和最近错误 |
| 每张工单的执行分支 | Ticket 标题、当前 Assignment、Worker Session 状态、最近有依据的操作或报告 | 授权、历次派工、Input 到达和读取、工具操作类型与结果、等待人工、恢复和重试。展开 DshExecutor 或 Sessions 查对应的 Session 与工作目录 |
| PR 与原会话 | 每个分支自己的 PR 状态、回复目的地及回执。GitHub 后续事件沿订阅线回到相关工单 | PR 创建前后的工单历史、审查和 CI 事件、PR 关联依据、接单确认、回复与通知的发送状态和失败原因 |
| Runtime 与 Store | 顶部显示运行时就绪、暂停、连接状态与数据更新时间 | 展开 Runtime 查看 Setup、Passes、SourceRegistry 等组件状态。展开 Store 查看事件游标及持久化状态。Policy、Prompts 与 MasterAssessor 的细节从相关路由或会话进入 |

- **新任务。** 来源 → Trigger → Thread → Eval / Gate → Router → Decision → Ticket → Assignment → Worker。来源过滤和准入拒绝落在各自的节点。显式请求可直接路由，模型研判按实际事件展示。
- **已有工单的跟进。** 来源 → Thread → Subscription → Ticket Input → Effects delivery → Worker。已结束工单符合恢复条件时，先校验原授权，再在同一个 Ticket 下生成新的 Assignment，通过 launch 重新启动。
- **输出。** Worker Report 更新 Ticket，按现有规则通过 relay 通知主 Session。PR 关联是独立的交付事件。回复和通知由 Outbox 通过 Channel 发送。图分别显示报告就绪、PR 状态与回复回执。

主图默认展开在途工单，近期完成记录可按需查看。点击某个 PR 时高亮相关工单路径，其他并行任务仍可见。关联线表示共享上下文，消息线只在观测到实际流转时高亮。工单、派工和 Worker 回合分别显示状态，重试或恢复在原工单中增加派工记录。只有工具或作业事件支持时才显示「正在跑测试」等操作描述。

## 开发顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 细化只读预览 | 在现有 `scripts/observatory-preview` 的快照里加入 Thread、Trigger 去向和 Ticket Input。按实际订阅投递记录绘制跟进线。拆开 Engine、Router、Effects、Ticket 和 Worker，保留 PR 与回执详情。将 `Assignment.startedAt` 对应的标签校正为「派工已启动」 | 已存工单能查到来源、Router 决定、派工及 PR 前序历史。有记录的跟进能展开查看去向和读取状态，缺少的时间显示「未记录」 |
| 2. 接入正式观测数据 | 在 Runtime、Engine、Effects、DshExecutor 与 Outbox 的边界补齐类型化事件。先完成跟进的接收、分发、投递、读取链路。随后补派工、回合、槽位、PR 绑定和回执。使用既有 Store 事务保存可持久化事件，提交后通知订阅端 | 每条消息能串起 `triggerId`、`threadKey`、`ticketId`、`inputId` 与实际接收的 `assignmentId`。事件在状态提交后可读。重试、重复通知或服务重启不把同一次交付画成多条消息 |
| 3. 接入管理端与实时更新 | 管理端读取同一快照里的状态和游标，沿用本机同源检查及管理请求头，通过 SSE 增量更新。客户端按事件序号去重，断线后补齐，从 PR 入口查询关联事件。展示 Worker 回合、工具操作和真实占槽状态 | 断开重连期间发生的事件能补齐，刷新仍能查历史。图只更新受影响的分支，详情选择保留。GitHub 侧展示原始事件时间和本机收到时间 |
| 4. 联调与验收 | 用两张并行工单检验路由、占槽、PR 关联和回复。一个 Worker 等待 PR 审查时，给它的 PR 加入一条人工跟进，另一个 Worker 继续执行。补充无 PR、重试、投递失败、人工停止与恢复场景 | 跟进沿已记录的订阅路由回目标工单。目标 Worker 的输入及回合变化可查。未命中订阅的工单不接收这条输入。PR 历史可回查到关联之前，并区分工单共有事件与 PR 专属事件 |

阶段 1 复用预览已在读取的管理快照和只读数据。正式版通过管理 API 读取观测数据。现有记录可提供 Decision 时间、派工创建与开始、PR 关联关系和回执状态。准确的槽位分配、回合开始、逐次投递时间和 PR 绑定时间由对应组件采集。投递耗时只在两端都有真实时间时计算。旧输入缺少精确读取时间时，按已有兼容语义显示已读取或时间未记录。

## 优先验收的跟进回流

例子里 Ticket A 已关联 PR 并等待审查，Ticket B 仍在执行。审查者在 A 的 PR 留言。GitHub 来源收到评论后生成 Trigger，Engine 根据 PR Thread 的订阅将评论加到 A 的 Input，随后将输入送到当前 Assignment 的 Session。Worker 空闲时会按执行器规则唤醒。如果 A 已结束但仍可恢复，图上记录原工单恢复及新派工。B 的路径按自身状态继续更新。

同一条跟进可以展开以下时间点和依据。

1. **收到。** 看 GitHub 上的评论时间、本机接收时间、PR 和消息链接。GitHub 使用轮询，因此两种时间分别显示。
2. **分发。** 看 Thread、实际命中的 Ticket、Input ID 和订阅关系。历史使用触发去向和输入事实，避免用当前订阅反推过去。
3. **投递。** 看输入在队列等待、投递失败重试，或已送达哪个 Assignment 的 Session。送达表示消息进入收件箱。
4. **读取。** Session 把该消息纳入回合上下文时记为已读取。随后分别展示 Worker 报告、PR 更新与回帖事实。

同一 Thread 可以订阅多张工单，图展示实际分发到的每一张。仅为上下文跟随的工单可以收到输入，这种跟随既不授予权限，也不会恢复已结束的工单。人工停止的工单不接收跟进，机器人和 CI 消息不会唤醒已结束的工单。对于没有现有工单接手、仍需评估的消息，图按其实际去向显示评估或后续交回。

### 联调验收清单

- [ ] A 等待 PR 审查、B 仍在执行时，在 A 的 PR 留言「补一个边界测试」。图上高亮 PR 线程到 A 的订阅路径，B 继续显示自己的进度，工单数保持不变。
- [ ] 点开高亮路径，核对 GitHub 评论时间、本机接收时间、目标工单及派工。能分别看到「已送达」与「已读取」。Worker 的后续报告和实际发出的回复可从该 PR 的时间线查到。
- [ ] 对已结束且仍可恢复的 A 再发一条人工跟进。图上在原 Ticket 下显示新 Assignment，从同一 PR 仍能查到恢复前后的记录。

## 验证范围

- 复用现有 `sources`、`runtime`、`runtime-concurrency` 和 `http` 测试夹具。覆盖正常扇出、同线程多工单、仅上下文订阅、结束后恢复与人工停止、已投递但未读取、失败重试和旧记录。
- 验证两条并行分支各自更新。分别点开 Thread → Ticket、Ticket → Worker、PR 和回复，核对时间、接收者与依据。验证图与 PR 时间线引用同一事件。
- 验证 SSE 游标衔接、事件去重和无历史时的提示。验证 Worker 空闲、排队等待、回合执行和实际占槽均可区分。

## 当前实施

本机预览已显示线程、引擎、队列和工单分支，PR 详情已接入对应线程的跟进。运行时已持久化接收、分发、送达、读取、PR 绑定与回执等事件，管理 API 提供快照和可续传的 SSE。预览收到 SSE 事件后刷新真实快照，保留轮询以读取队列和槽位等即时状态。

两张工单的 PR 跟进、原工单恢复、送达与读取区分，以及 SSE 回滚和续传已使用测试夹具验证。真实 GitHub 的双工单联调仍按验收清单执行。工具级操作摘要和各队列的逐次等待原因留待补齐。
