# 005 面板

> 本文为中文译本，内容以英文原文为准：[原文](005-panel.md)。

在 DeepSeek Harness Web 侧边栏中打开 **Superagent**，以监督智能体。面板优先展示需要人工处理的工作，其次是系统健康状况与历史记录。本文建立在 [000 理念](000-philosophy.zh-CN.md) 至 [004 提示词](004-prompts.zh-CN.md) 的基础之上。

## 三个问题

打开面板会按以下顺序回答三个问题：

1. 现在有什么需要我处理吗？
2. 系统是否健康，是否在做正确的事？
3. 一项工作从触发（Trigger）经评估（Eval）到工单（Ticket）的历史是怎样的？

## 标签页

标签页沿工作流排列：**概览（Overview）**、**来源（Source）**、**触发（Trigger）**、**评估（Eval）**、**执行（Execution）** 和 **设置（Settings）**。在仓库与账户配置成功之前，概览页会显示缺少什么，并链接到相关设置。

| 标签页 | 显示内容 |
| --- | --- |
| 概览 | 需要处理的工单、系统问题、过去 24 小时的活动计数，以及执行器负载。每个区块都链接到其详细页面 |
| 来源 | 来源状态、配置问题和非零计数。被过滤的触发和被丢弃的消息与概览使用相同的 24 小时窗口 |
| 触发 | 按已订阅、评估中、24 小时内新增触发或全部线程筛选的线程。每个线程按从新到旧的顺序显示其触发、决定和订阅 |
| 评估 | 带有原因和所匹配规则的决定 |
| 执行 | 执行器状态、暂停处理，以及按未结、待处理、处理中、等待触发或已结束筛选的工单。工单详情显示可执行的操作、授权、等待中的输入、订阅和派工 |
| 设置 | 来源、评估、执行、提示词和部署。每组都包含其保存历史 |

### 查看单条记录

被丢弃的消息会链接到其工单；若没有工单，则链接到其线程。来源页会说明是该对话消失了，还是来源已停止监听它。

仍由某个执行器负责的人工跟进消息会被标记为 **已交付到工单（Delivered to Ticket）**，且不经过评估。线程还会显示交回原因和仅作上下文的订阅。**再次评估（Evaluate again）** 可以将该跟进消息送入评估，也可以重试一个未得到有效判断的触发：该触发被其来源过滤、评估不可用，或者消息已交付但既没有非停止的决定，也没有执行器的确认。

工单详情显示来源触发、决定及原因、范围和策略版本（Policy version）。派工和次要细节折叠在即时操作之下。对于输入投递失败，或因报告被阻塞或失败而等待人工处理的工单，可使用 **重试（Retry）**。已结束的工单会显示结果，例如 **拉取请求已合并（Pull request merged）** 或 **已由人工停止（Stopped by a person）**。

## 设置分组

- **来源：** 每个来源一张卡片，包含其开关、字段和已验证的账户信息。GitHub 还为新 Issue、拉取请求、评论和默认分支 CI 提供全量接收开关。轮询和读取限制位于高级设置下。
- **评估：** 策略版本和规则，随后是 **每个来源（On each Source）** 和评估设置。每个来源标签页包含其允许列表、成员同步、准入表和机器人列表。同步在启动时以及点击 **立即同步（Sync now）** 时运行。准入表区分接收范围、发送者成员资格，以及消息是否指向智能体。评估设置用于选择接单模式（accept mode）、超时和研判模型。
- **执行：** worker（执行器 Session）模型、并发数、目录根路径、准备命令和被阻止的命令。点击可用变量会将其插入准备命令。
- **提示词：** **编辑（Edit）** 可修改团队段落、内置部分和技能。**完整提示词（Full prompt）** 显示组装后的文本，并与已保存的文本或默认值比较。**历史（History）** 列出各版本。被编辑的内置部分会标记为已更改，并可以重置；模板会列出其必需的占位符。

  当升级改动了某个被覆盖的默认内容时，会将其标记为 **默认内容已更新（Default updated）**。面板会在团队文本上方比较新旧默认内容。如果没有记录旧的默认内容，则改为将团队文本与新默认内容比较。请选择 **保留我的文本（Keep my text）** 或 **使用新的默认内容（Use the new default）**。已移除部分对应的覆盖项列在标签栏下方，并在下次保存时丢弃。
- **部署：** 包含 **再次检查（Check again）** 的启动问题、状态目录和机器限制。已保存的限制无需重启即可生效。DeepSeek Harness 插件管理器会展示同一页面。

## 搜索

页眉搜索可按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原始消息中缺失的飞书链接，只有在宿主于当前进程生命周期内读取到它之后才可被搜索。

搜索还可以按 `#12` 或 GitHub URL 等引用查找线程，并按标题或匹配的线程查找工单。

## 原则

1. **聚焦重要之事。** 每个元素都要回答三个问题之一，否则就移除。数字只有在能改变监督者行为时才会出现。
2. **精确定义。** 类别具备可核查的定义、彼此互斥且覆盖所有情况，正如工单阶段那样。标签说明某一行在等待谁、需要什么，而不是内部状态码。
3. **一个概念一处。** 来源状态归来源；线程和触发归触发；决定归评估；工单归执行。设置按其所配置的概念分组。概览对这些页面做汇总并链接到它们，而不是变成另一个详细视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节中，能够解析出名称的地方用名称替代标识符。
5. **状态诚实。** 计数等于其链接列表的长度，且任何状态都不得与其他事实相矛盾。
6. **默认安静。** 健康状态不占用额外空间。问题必须可操作；一次性的网络错误不算。需要人工处理的行直接提供其操作。页面说明保持一句话，更多细节放在 (?) 提示框中。破坏性操作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌和控件行为。相同信息在面板各处应看起来一致。每个设置区块只有一个保存栏，仅在有更改、正在保存或保存失败时可见。
