# 000 理念

> 本文为中文译本，内容以英文原文为准：[原文](000-philosophy.md)。

dsh-superagent 是一套框架，也是一种与智能体协作的工作方式。其核心原则是：

**尽可能少占用人的注意力，尽可能多地提供价值。**

项目中的每个部分都以其消耗的注意力来衡量。一条消息、一条通知、一个问题、一个设置、一个面板元素和一段文档，每一项都消耗某人的注意力，因此每一项都必须带来超过该消耗的价值，否则就会被移除。

## 对智能体的要求

- **只在被要求时行动，或在书面规则允许时行动。** 只有直接指向智能体、且来自团队允许之人的请求才算数：允许列表上的人，或团队已开放接单的会话中的任何人。无人要求的工作需要团队写下的规则，并以只记录智能体本会如何行动的模式启动。
- **只在人必须行动或能使用结果时才发言。** 它对请求只确认一次，并说明将要做什么。工作时保持安静。当结果就绪、需要决定或无法完成时，才再次发言。消息简短，并发送到提出请求的那段会话。
- **一次只问一个具体问题，** 并以结构化形式提出，让问题直达当事人，而不是埋在长报告里。
- **以影响而非投入决定何时停止。** 局部改动推进到可评审的结果为止。需要设计决策的改动则带着明确问题停下。
- **如实报告。** 草稿标明未完成，失败就报告为失败，绝不为了回避询问而绕过限制。

## 对设计的要求

- **概念要少。** 设计只包含其领域概念（如来源）及其具体实现（如 GitHub 与飞书）。业务需求会变成其中某个概念的属性，或智能体遵循的提示词，而不为它新增概念。
- **设置要少。** 当某个取值几乎适用于所有团队时，用默认值取代设置。团队用文字描述的行为属于提示词文本，而不是设置。
- **面板只展示需要人处理的内容。** 它首先列出等待人处理的事项。健康状态不占用空间。
- **文档按顺序阅读。** 每篇编号文档只建立在它之前的文档之上，因此读者永远不需要尚未引入的概念。

## 责任

智能体以团队每天都能看到的账号发表评论、开启 PR 并给人们发消息。它发送的每条消息都消耗同事的注意力，而你对此负责。智能体能做的事越多，其操作者（Operator）对团队的责任就越大：

- **从小范围开始。** 先使用简短的允许列表，并让主动（proactive）工作只被记录。当智能体本会做的事看起来正确后，再放宽这两者。
- **调低噪声。** 当智能体噪声过大时，把提示词改得更短更严格，或暂停它。不要增加更多消息来解释噪声。
- **不要用它制造数量。** 批量 PR、广播消息和无谓忙碌，给团队带来的消耗大于价值。
- **对它所说的话负责。** 阅读智能体以你的名义发布的内容，若有错误，在提示词中纠正。

目标是：在正确的时间提供正确的帮助，其他时间一概不打扰。
