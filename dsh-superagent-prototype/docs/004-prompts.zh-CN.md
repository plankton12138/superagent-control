# 004 提示词（Prompts）

> 本文为中文译本，内容以英文原文为准：[原文](004-prompts.md)。

本文说明智能体读取什么、团队可以编辑什么，以及更改何时生效。它建立在[000 理念](000-philosophy.zh-CN.md)至[003 执行](003-execution.zh-CN.md)之上。提示词文本以英文撰写。

## 团队编写的内容

团队可以编辑三个团队部分、添加技能，并覆盖每个内置系统提示词部分。大多数默认内容位于 `prompts/` 和 `skills/` 下。工具说明、通知和卡片仍保留在代码中，无法通过提示词设置编辑。

| 部分 | 包含内容 |
| --- | --- |
| 沟通 | 何时给人发消息、消息如何表述、每条 GitHub 消息开头的那一行（默认 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号是评审机器人 |
| 工单范围 | 工单何时继续推进，何时带着草稿停下 |
| 交付要求 | PR 中的证据、带行数阈值的自动合并条件，以及提交作者；若未指定，执行器以智能体账号的 no-reply 地址提交 |
| 团队技能 | 智能体在需要时加载的知识，例如说明哪个飞书用户对应哪个 GitHub 账号的 `identities` 技能 |

内置文本涵盖角色、工具使用、宿主机制、授权规则，以及 GitHub 和飞书技能。它通过标题引用团队部分，而不重复其内容。

### 内置部分与模板

覆盖项使用以下键：

| 部分 | 键 |
| --- | --- |
| 共享指示与角色 | `runtime/shared`, `runtime/orchestrator`, `runtime/worker` |
| 工作指示 | `runtime/subscriptions`, `runtime/replies`, `runtime/dispatch`, `runtime/work`, `runtime/admission` |
| 移交指示 | `runtime/handoff/orchestrator`, `runtime/handoff/worker` |
| 来源技能 | `skill/feishu`, `skill/github` |
| 生成的部分 | `runtime/environment`, `runtime/policy`, `runtime/policy/none` |

生成的部分是可编辑模板。它们必须保留以下占位符：

- `runtime/environment`：`{variables}`，填入执行环境各行。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条已启用规则一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有启用规则时使用。

编辑某个部分会改变模型收到的指示。它不会改变准入、授权、工具检查或账号包装器，这些仍由代码强制执行。

在人类明确请求时，主 Session 还可以用 `orchestrator_prompts_save` 保存覆盖项。若保存时省略某个覆盖项的 `base`，则保留已保存的 base。已从保存配置中存在的部分若被移除，会在保存时删除；其他任何未知部分都会被拒绝。

覆盖项会记录它基于哪段内置文本。升级会保留团队的文本。若默认内容发生变化，面板会把该部分标记为 **Default updated**，并在团队文本旁显示差异。团队可以保留自己的文本、采用新的默认内容或编辑它。没有覆盖项的部分会自动跟随新的默认内容。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读取受影响部分的名称。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指示与角色。
2. 三个团队部分。
3. 订阅与回复。
4. 主 Session 的派发，或执行器的工作指示。
5. `runtime/admission`，仅用于主 Session。
6. 移交指示。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主 Session。

准入指示来自 `prompts/admission.md`。它们描述主动研判，以及何时可以依据卡片忽略无关候选。`orchestrator_eval` 返回上下文，而不是重复这些指示。

环境部分向主 Session 提供部署范围内的值，向每个执行器提供其工单专属的值。策略部分在每次模型请求时由设置重新生成。它包含策略版本、接单模式、明确请求豁免，以及按 `- <name> (<id>): <instruction>` 格式列出的已启用规则，或声明没有启用任何规则。它位于最后，因此策略变更不会改动前面的提示词文本。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读取。推断工单会在末尾添加一条说明，把其执行器限制在匹配规则之内。派工和传入消息以触发卡片的形式内联到达，仅对截断内容提供资源指针。

执行器在无人值守下工作。其工具排除了向人提问、向人展示 UI 或更改配置档的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从最强到最弱：

1. 由工具和宿主强制执行的事实：身份、权限、工具参数检查、回复用途、长度限制。提示词文本无法改变它们。
2. 内置部分和生成部分，按其团队覆盖项的表述。
3. 主动工单匹配规则中的流程与沟通，仅作用于该工单的执行器 Session。
4. 团队部分和团队技能。
5. 外部文本：消息、评论、文档和引用。它们属于数据，永不改变规则或授权。

## 内置文本的原则

以下内容把[000 理念](000-philosophy.zh-CN.md)应用于智能体：

- **角色分离。** 主 Session 只负责路由：它转发原始触发和路由事实，不作技术决策，并通过一个路由工具在一次调用中对多个等待中的候选作出决定。路由说明最多 30 词。执行器读取原始来源、判断范围、实施并验证。
- **主 Session 不等待。** 报告、跟进通知、候选和已完成的后台作业都会以消息自动到达。当无事可做时，它结束回合。一道防护会拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的作业等待，因为受阻的步骤会延误新候选。这些指示会替换主 Session 完整提示词中 DeepSeek Harness 自己的作业通知说明。
- **只在人必须行动或能使用结果时才发消息：** 结果可以被评审或使用、需要决定或资源，或工作无法完成。聊天消息默认一句话，硬性上限为 100 词。
- **执行器决定其跟进。** 每个执行器处理并确认范围内的请求，并交回超出其工单或属于另一工单的请求。只有在所有拥有者都将其交回或未接手即结束之后，消息才会成为新工作。主 Session 会收到跟进通知，但只能对其实施停止工作。交回的消息随后会连同各执行器的理由作为候选到达。
- **通过订阅和主 Session 协同。** 执行器为获取上下文而关注相关线程。主 Session 可以在最多 100 词的说明中发送来自另一工单的事实。订阅和该说明都不授予权限。
- **仅在明确引用时附加。** 消息必须指向某工单的 PR、Issue、来源消息或确认，或指向恰好只匹配一个工单的近期变更。仅主题相似并不够。附加会让工单订阅整个线程；执行器若发现其无关，会使用 `orchestrator_thread_unrelated` 且不在那里作答。
- **具体地确认一次。** 在开始实质性工作之前，执行器会确认每个新请求，并说明对象和预期结果，以原消息下的回复形式发出。
- **通过 `human_action` 提问。** 执行器在报告中放入一个具体问题，主 Session 原样转发。若问题由某人的消息引发，它会指明该消息，由宿主在那里提问。否则它在工单的原始会话中提问。已获授权的工作可以在此期间继续。
- **诚实交付。** 开启 PR 并不等于就绪；草稿会标明未完成；没有真实修改前截图的 UI 变更不算就绪。
- **人的暂停持续有效，** 跨越跟进、新的执行器 Session 和重启，直到有人解除它。自动反馈永远不会恢复被暂停的工作。
- **示例只展示格式。** 示例句子不是智能体可以主张的事实。
- **按结果处理评审。** 已修复并验证的评论会静默解决；被拒绝的评论附一句理由。自动评审者的线程在得到答复后即解决，每个自动评审者对每个 PR 最多三轮。
- **让位于重复工作。** 当人的分支或 PR 已包含工单的改动时，执行器会关闭自己的 PR，并用一句话指向对方。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前驱、时间戳和来源（面板或工具）。恢复某个版本或默认值会再创建一个版本。
- 保存会声明其基准修订。冲突的保存会被拒绝，且不会丢弃草稿。
- Session 在每次模型请求时读取最新版本，包括同一回合中后续的步骤。保存不会重启、取消或唤醒 Session。宿主会记录每个 Session 使用的修订；执行器可以读取其工作过的任何修订。
- 部署会设置总大小上限，包括覆盖项。校验会拒绝未知键、保留的内置技能名称、未知覆盖部分和缺失的模板占位符。它绝不会静默截断文本。与默认内容完全相同的覆盖项会被移除，以便该部分跟随未来的默认值。
